# ARS Authenticated UI/UX Critique

Method: dual-agent assessment of the authenticated application. Landing excluded.

## Score

26/40. The academic visual system is credible, but task prioritization and operational affordances need refinement.

## Priority Issues

1. P1: Remove or resolve dead shared navigation. Account Settings has no registered route and wallet destinations are disabled.
2. P1: Replace backend implementation terminology with user-centered, supported next steps in Lecturer and Graduate Student blocked workflows.
3. P2: Reprioritize mobile header controls; retain menu and notifications and move account-related controls to a compact secondary surface.
4. P2: Group Admin navigation and translate technical publication statuses into user-facing stages with progressive disclosure.
5. P2: Add accessible menu/dialog semantics, Escape handling, focus management, and labels to shared overlays.

## Strengths

The token palette, restrained editorial typography, shared state components, and truthful Guest forum access make the platform feel appropriate for academic work.

## Evidence

The detector found 18 in-scope warnings: repeated left-border treatments, five width transitions, and shared accessibility issues in the Forum composer/profile dropdown/toast close button. Inter font and status-toast border flags were assessed as low-value or false-positive signals.

## Personas

Researchers face status overload and a nonfunctional global search. Graduate students encounter disabled high-stakes actions without an equally visible alternative. Administrators must scan eleven ungrouped destinations.

## Recommendations

Make each role workspace foreground the user’s next academic decision, remove nonfunctional affordances, and preserve the current quiet research-oriented visual system while reducing repeated decorative header content.
