# BE Ticket: Authoritative Reviewer Policy Acceptance and Manuscript Access Gate

## ID

BE-REVIEW-POLICY-GATE-04

## Priority

High

## Background

The frontend displays a Reviewer Policy modal before mounting the manuscript PDF viewer. Browser state is intentionally non-authoritative and only defensive. The backend must record acceptance per review assignment and policy version, then enforce it before returning any protected manuscript document URL or content.

## Goal

Require an accepted current reviewer policy for a specific review request before allowing manuscript/PDF access, and provide APIs for the frontend to query and record that acceptance.

## API Contract

### 1. Get policy status

`GET /api/ReviewRequest/{reviewRequestId}/policy-status`

Return only for the assigned reviewer or authorized administrator.

```json
{
  "reviewRequestId": 456,
  "paperId": 789,
  "policyVersion": "2026-08-22",
  "policyAccepted": false,
  "acceptedAt": null,
  "policyDocument": {
    "title":  "Reviewer Confidentiality and Conduct Policy",
    "version": "2026-08-22",
    "contentUrl": "https://app.example/legal/reviewer-policy/2026-08-22"
  }
}
```

### 2. Accept policy

`POST /api/ReviewRequest/{reviewRequestId}/policy-acceptance`

```json
{
  "policyVersion": "2026-08-22"
}
```

Return the authoritative status, including `acceptedAt` generated by the server.

### 3. Obtain protected manuscript access

Either update the current manuscript/document endpoint or add a dedicated endpoint such as:

`GET /api/ReviewRequest/{reviewRequestId}/manuscript-access`

Only return a short-lived document URL or stream content after assignment and policy acceptance are verified server-side.

```json
{
  "reviewRequestId": 456,
  "paperId": 789,
  "documentUrl": "short-lived-signed-url",
  "expiresAt": "2026-08-22T15:15:00Z"
}
```

## Authorization and Enforcement Requirements

- Verify the JWT subject is the assigned reviewer for the given review request, or is an authorized administrator.
- Verify the review request is active and the reviewer is still eligible to review.
- Store acceptance keyed by `ReviewRequestId`, reviewer/user ID, and `PolicyVersion`; never key it only by paper ID.
- Treat a policy-version change as requiring new acceptance.
- Make acceptance idempotent for the same request/version/user. Do not create duplicate rows.
- Generate the acceptance timestamp server-side and audit user ID, review request ID, policy version, timestamp, and correlation ID.
- The manuscript/PDF endpoint must reject access without current policy acceptance, even if the caller discovers a previous URL or manipulates frontend/session storage.
- Prefer short-lived signed URLs; do not expose permanent Firebase/public URLs for reviewer-only manuscripts.
- Return `403 PolicyAcceptanceRequired` when the assignment is valid but acceptance is missing or stale.
- Do not rely on a frontend-provided `policyAccepted` boolean, localStorage, or sessionStorage.

## Data Requirements

Add or reuse a policy-acceptance entity with at minimum:

- `ReviewRequestId`
- `ReviewerUserId`
- `PolicyVersion`
- `AcceptedAt`
- `CreatedAt`
- audit/correlation metadata as applicable

Enforce uniqueness for the assignment/user/version tuple.

## Acceptance Criteria

- Before acceptance, an assigned reviewer can obtain permitted non-sensitive paper metadata but cannot obtain or view the protected manuscript document.
- Accepting the policy for Review Request A does not unlock Review Request B, including when both reference the same paper.
- Changing the policy version relocks document access until the reviewer accepts the new version.
- Repeated acceptance requests are idempotent.
- Unassigned users and reviewers with revoked/closed requests cannot query acceptance status or obtain document access.
- Document URLs, when used, are short-lived and unavailable after expiration.
- Swagger documents all endpoints, roles, success responses, and `401`, `403`, `404`, and validation errors.
- Tests cover assignment boundaries, policy version changes, duplicate acceptance, direct document-access bypass attempts, and URL expiry.
